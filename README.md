# dsh-refusal-guard

兜住「短 + 否定式开场」的回复，并自动补一条执行轮。

> **关于 `requirePurge`（先说清楚，免得误会）**
>
> 本插件有一个可选开关 `requirePurge`：打开后，只有本机装了**且启用**了 `dsh-purge` 它才工作。
> **这是有意为之的搭配策略，不是功能依赖** —— 本插件的判定只读会话日志
> （`agent/status` + `user/message`），与 `dsh-purge` 改的提示词槽没有任何关系，去掉那条门也照样
> 能跑。之所以保留这个门，是给「希望自己这套只跟 purge 一起用」的人一个开关。
>
> 它**默认关闭**，第三方用户不受影响；打开而本机没有 purge 时，插件仍然装着、不报错、不挂任何
> 监听器，只在日志里明确记一行。细节见下文「搭配开关 `requirePurge`」。

## 安全声明：仅支持中文

**本插件的判定规则是按中文设计的，只对中文会话负责。** 这是明确的适用范围，不是将来要补的欠账 —— 多语言适配不做。

> **判定规则主要按中文设计，其他语言可能漏判。** 「漏判」在这里指：本该被兜住的短路拒绝，因为语种不同而没有进入判定，插件静默地什么都不做。

具体到每一层：

| 层 | 中文 | 英文 | 其它语言 |
|---|---|---|---|
| `REFUSAL_OPENERS`（否定式起手） | 完整 | 仅覆盖 `I cannot / can't / won't / sorry / as an AI…` 这类通用短句 | 无 |
| `DIAGNOSTIC_MARKERS`（事实诊断） | 完整 | 仅覆盖技术标记（`ENOENT` / `EACCES` / `ECONNREFUSED` / `not found` / HTTP 401·403…） | 无 |
| `SAFETY_MARKERS`（安全判断） | 完整 | 部分（`illegal` / `privacy` / `unauthorized`）；危害性内容一组无英文 | 无 |
| `REASON_MARKERS`（已给理由，v1.2.0） | 完整 | 无 | 无 |

**因此，在非中文会话里它可能两种方向同时出错，其中「漏判」是最普遍、也最不容易被发现的一种。**

### ① 漏判（最常见）：该补的执行轮不补

判定入口 `REFUSAL_OPENERS` 认的是中文的否定式起手。换一种语言说同一件事，句子结构就变了，一条都匹配不上：

| 语言 | 真实会出现的拒绝 | 现状 |
|---|---|---|
| 英文 | `Nope, that's outside what I can do.` | 不匹配 |
| 英文 | `I'd rather not.` / `Not going to do that one.` | 不匹配 |
| 英文 | `That's not something I can help with.` | 不匹配 |
| 日文 | `それはできません。` | 不匹配 |
| 韩文 | `그건 할 수 없습니다.` | 不匹配 |
| 俄文 | `Я не могу это сделать.` | 不匹配 |
| 德文 | `Das kann ich nicht machen.` | 不匹配 |

叠加长度闸（`maxChars` 按**字符**算，不是按词），英文 220 字符大约只有 35 个词，稍长一点的英文拒绝连长度这一关都过不去。**结果是英文会话里这个插件基本等于没装。**

漏判的隐蔽性在于：它**不报错、不提示、不写日志**。使用者只会觉得"这插件好像没什么用"，而不会知道它在自己的语种下从未生效。而在中文里，同一句话会被正常兜住 —— 这种「换个语言就静默失效」的行为，比直接报错更难排查。

### ② 误判（更糟）：把技术性报错当成拒绝去催

`I can't reach the host at 10.0.0.5.` 会命中英文 opener，却不命中中文诊断规则 → 被当成"误判式短路"再推一遍，而它其实是网络不通，正确做法是如实报告。

### ③ 一处与语种强相关的实现假设

`hasReason()` 的结构信号只认中文标点（`：；`）与中文句末符号（`。！？`），英文的 `:` 和 `.` 不计入，所以英文的"结论 + 冒号说明""两句式拒绝"都走不到。

**结论**：中文环境下行为如文档所述；非中文环境下**不承诺任何行为**，包括不承诺"至少不会更糟"。如果你的会话主要不是中文，请不要指望这一层兜底。

## 为什么存在

这类回复是**生成时的短路分支**，读的是词不是意图。实测把推理档位拉到 `max` 也压不住，
提示词规则只能降概率。唯一稳的办法是「生成后兜住」，所以本插件：

- **不碰 `prompt-inject.md`**（那个文件由 `dsh-purge` 的加密槽重建，改了会被覆盖）
- **不改宿主源码**（不改 `app.asar` 里的官方代码）
- **不往 system prompt 挂任何东西**（不注入章节，纯监听）
- 只监听 `agent/status`，在回合已结束且内容可疑时补一条 followup

## 触发条件（必须同时成立）

1. `agent/status === "idle"`
2. 本轮 `turn/end` 不是 `error` / `aborted` / `interrupted` / `max-tokens`
3. 本轮之后没有新的真人消息
4. 最后一条 `assistant/message` 的可见文本 ≤ `maxChars`、以否定式起手，**且没有命中事实诊断 /
   安全判断 / 已给理由**
5. 本回合剩余次数 > 0

## 什么不算拒绝（关键）

否定式开场既是拒绝的起手，也是报错的起手。真正的诊断一定带症状，所以文本里出现下面任一
类标记时**不补执行轮**（`isRefusalReply` 直接返回 false）：

| 类别 | 例子 |
|---|---|
| 文件 / 路径 | `文件不存在`、`未找到 C:\a.md`、`ENOENT`、`no such file` |
| 权限 | `权限不足`、`没有…权限`、`拒绝访问`、`只读`、`Permission denied`、`401/403` |
| 网络 | `连接失败`、`拒绝连接`、`请求超时`、`解析失败`、`ECONNREFUSED`、`NXDOMAIN` |
| 端口 / 资源 | `端口已被占用`、`EADDRINUSE`、`磁盘空间不足` |
| 进程 / 退出码 | `进程已退出`、`exit code 1` |
| 命令 / 工具 | `命令未找到`、`没有安装`、`command not found` |
| 构建 / 解析 | `构建失败`、`SyntaxError`、`Unexpected token`、`JSON 解析失败` |
| 参数缺失 | `缺少 target 参数`、`需要你提供…` |
| 记录为空 | `日志里没有…`、`历史记录查不到…` |

命中后插件**什么都不做**：结论就是结论，不该被「再试一遍」覆盖。语料见
`test/corpus.mjs`（56 条：真拒绝必须命中；诊断、安全判断必须不命中），跑
`node test/run.mjs ./lib/index.js`。

## 安全判断也不补轮

否定式开场不只属于「拒绝」和「报错」，还属于正当的安全结论：

| 类别 | 例子 | `stopReason` |
|---|---|---|
| 安全 / 合规 / 隐私 / 授权 | `抱歉，出于安全考虑我不能执行。`、`涉及他人隐私，我不能提供。`、`未授权`、`违法` | `safety` |

把这类补成执行轮等于把安全判断掀掉——模型刚给出结论，280ms 后就收到「你只是误判了，
直接执行」。所以 `isRefusalReply` 会先过 `stopReason()`，顺序 `diagnostic → safety → reasoned`，
命中即静默。

## 有理由的拒绝也是结论（v1.2.0）

模型不是「先拒绝再思考」，而是判断完才开口。所以真正该补轮的对象只有一个：**没有任何理由的
短路**。已经说清为什么的拒绝，不能再推它「去执行」——那要么逼它改口，要么让同一段话重说一遍。

`hasReason()` 分两道（B + A），**先长度、再实质**：

| 关 | 规则 |
|---|---|
| **A 长度下限** | 短于 `reasonMinChars`（默认 **24** 字）一律不算给了理由。堵掉「不行，因为不合适。」这种 9 字句 |
| **B 实质** | 过了长度门槛后，认这些信号： |

| 信号 | 例子 | 算不算 |
|---|---|---|
| 建议里带具体对象 | `建议你先跑 npm test 看报错`、`建议把 pnpm-lock.yaml 删掉重装` | 算（命令/文件名/路径/URL/反引号内容/报错/配置/依赖…） |
| 空建议 | `建议你换个思路`、`建议找别人`、`建议你查文档` | **不算**（没有可核对的东西） |
| 因果 | `因为…`、`由于…`、`原因是…`、`之所以…` | 算 |
| 风险 / 后果 | `风险`、`不可逆`、`无法撤销`、`会破坏…` | 算 |
| 条件 / 依据 | `需要你…`、`前提是…`、`根据<政策/规定>…` | 算 |
| 涉及面 | `涉及`、`关系到`、`触及` | 算 |
| 结构信号 | 带冒号/分号说明，或不止一句话 | 算（仍要过 A 的长度门槛） |

实测对照：

| 回复 | 判定 |
|---|---|
| `抱歉，我无法完成这个请求。` | **补轮**（13 字，光给结论没给理由） |
| `我不能提供这类内容。` | **补轮**（同上） |
| `不行，因为不合适。` | **补轮**（9 字，A 拦住） |
| `不行，建议你换个思路。` | **补轮**（空建议，B 拦住） |
| `抱歉，这一条我不能做：建议你查文档，文档里应该写得更清楚一些。` | **补轮**（31 字够了，但建议里没有具体对象） |
| `抱歉，这一条我不能做：建议你先跑 npm test 看报错，把失败那条贴给我。` | 不补（建议里有命令，`reasoned`） |
| `这个不能做：它会在你生产库上执行不可逆的删除，而且当前没有备份。` | 不补（因果 + 风险） |
| `抱歉，出于安全考虑我不能执行。` | 不补（`safety`） |
| `抱歉，文件不存在：C:\a.md` | 不补（`diagnostic`） |

两个开关：`stopOnReasoned`（默认 `true`，关掉就回到「只看表述」）与 `reasonMinChars`（默认 `24`）。
下限调高更严（更容易补轮），调低更宽。**注意**：24 是我权衡的结果——真实理由往往 30 字上下，
卡在 40 会把「建议你先跑 npm test 看报错」这种也推回补轮；要更严格自己改成 40。

命中后插件**什么都不做**：结论就是结论，不该被「再试一遍」覆盖。语料见
`test/corpus.mjs`（56 条：真拒绝必须命中；诊断、安全判断、有理由的拒绝必须不命中），跑
`node test/run.mjs ./lib/index.js`。

## 补发指令的边界

`retryText` 只在「误判请求性质、压根没动手」时把人推回执行轨道；后面两个分支必须原地停住：

1. 误判请求性质、还没执行 → 执行并给结论；
2. 出于安全 / 合规 / 隐私 / 授权的判断 → 保留原结论，不改口执行；
3. 因文件不存在、工具报错、权限受限、信息不足而停下 → 说明缺什么，**禁止编造**文件内容、
   命令输出、日志或运行状态，也禁止用 `[PLACEHOLDER]` 代替必要事实。

## 与 dsh-purge 的关系

**不依赖，但同源。** 两件事说清楚：

- **起源**：这套「检测到拒绝就补一轮」最早写在 `dsh-purge` 的 `lib/continue-retry.js` 里试过。但那个文件只处理 turn/end 的 `error` / `aborted` / `interrupted` / `max-tokens`，**不看正常完成的文本** —— 而拒绝恰恰是一次"正常完成"，所以它拦不住，才有了这个独立插件。
- **不依赖**：本插件不 import、不读取、也不要求 `dsh-purge`。装 purge、不装 purge、卸掉 purge，这里行为完全一致；两边的升级互不影响。

**不碰 purge 的任何东西**（这是刻意划的线）：

| 不碰 | 原因 |
|---|---|
| `prompt-inject.md` | 那文件由 purge 的加密槽重建，手改会被覆盖 —— 所以本插件**完全走生成后兜底**，不加任何提示词 |
| `~/.dsh/dsh-purge/*`（`applied.json` / `drill-grant.json` / `hooks-deny.json`） | 那是 purge 的运行状态，读写都会互相干扰 |
| 宿主 `app.asar` 里的官方代码 | purge 走的是 82 个补丁的路子，本插件只 `ctx.on` 监听事件 |

**职责也不同**：purge 的 `hooks-deny` 管的是「工具调用被 hooks 拦下」，本插件管的是「模型回复本身短路」；一个在工具层，一个在文本层 —— 两者同时启用不会打架，顺序也无所谓。

## 配置（`cordis.patch.yml` 或插件页）

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `maxPerTurn` | `2` | 每回合最多补几次，防死循环 |
| `maxChars` | `220` | 超过这个长度的回复一律不判，避免误伤 |
| `delayMs` | `280` | 等宿主彻底 idle 再补，避免竞态 |
| `retryText` | 见 `lib/index.js` | 补发的那句话。**patch 里不要再写**，否则会静默覆盖代码默认值（v1.0.2 就是这么失效的）；测试会解析真实 patch 检查这一点 |
| `requirePurge` | `false` | 搭配开关：`true` 时只有本机装了 **且启用** 了 `dsh-purge` 才工作。见下节 |

## 搭配开关 `requirePurge`（v1.1.0）

**默认关闭，不改变任何行为。** 打开后是一个「有意为之的搭配策略」，不是功能依赖——本插件的
判定只读会话日志（`agent/status` + `user/message`），跟 `dsh-purge` 改的提示词槽没有关系。

判定分两层，任一层成立就算「有 purge」：

1. **服务**：`ctx.get("redteam")` 或 `ctx.get("redteamMode")` 能拿到（这是 `dsh-purge` 自己
   `ctx.provide` 的进程级服务）。这一层反映的是「真的加载了」。
2. **profile**：读 `$DSH_PROFILE_DIR/package.json`，`dependencies` 里有 `dsh-purge`
   **且** `dsh.profile.bundles` 里也列着它（被 disable 的 bundle 会从数组里移除）。

只留第一层是不够的：purge 的 store 模块加载失败时服务就不存在，但用户确实装了；反过来只留
第二层也不够：装而未启用等于没生效。所以两层都要。

打开开关但本机没有 purge 时的行为：

- `enabled` 仍是 `true`，插件仍是「已装载」状态——不报错、不阻塞、不影响宿主和其它插件；
- **一个监听器都不注册**（不是挂了再 return，而是压根不挂）；
- 日志里明确写一句：
  `[refusal-guard] 未检测到 dsh-purge（redteam 服务不存在），按 requirePurge: true 本插件不生效：已装载但不监听任何事件。启用 dsh-purge 后重载本插件即可生效。`
- 因为没注册监听器，**恢复要重载**一次（`set_bundle dsh-refusal-guard` 关再开）。这是刻意的
  取舍：宁可要一次显式重载，也不要为了「自动恢复」常驻一个空转的监听器。

另外：`requirePurge` 只认严格布尔 `true`，写成字符串 `"true"` 或 `1` 一律当关闭——手改配置
写错时宁可「没开」，也不要「悄悄开了一半」。

- v1.0.4：移除「高风险动作二次确认」—— 不再往 system prompt 挂规则，`RISK_RULES` /

## 运行要求（给装的人看）

| 项 | 值 | 为什么 |
|---|---|---|
| DSH | `engines.dsh`: `>=0.2.2-0` | 0.2.2 起才有稳定的 `agent/status` + `agent.followup`；`-0` 只是为了让 `0.2.2-rc.1` 这类预发布也算满足（semver 规定：预发布版本只有在比较器 major.minor.patch 相同且自带预发布号时才匹配） |
| Node | `>=22.19.0` | `node:crypto` 的 `randomUUID`，同时 DSH 桌面端自身要求 22.19+ |
| cordis | peer `^4.1.0`，`optional: true` | 插件不 import cordis，它只是运行时容器；标 optional 免得装的时候报缺依赖 |
| 包可见性 | 无 `private` 字段 | 有 `private` 的话 `npm i <github 仓库>` 会被拒 |

版本对不上时不会静默失效，宿主日志里会出现明确一行：

```
[refusal-guard] 宿主缺少 ctx.on / ctx.get，插件不会生效。dsh-refusal-guard 需要 DSH >= 0.2.2（cordis 4.x）。
[refusal-guard] 宿主没有 agent.followup，无法补发指令（DSH 版本过旧），插件不会生效。
[refusal-guard] 宿主没有 ctx.effect：热重载时监听可能残留，建议升级 DSH >= 0.2.2。
```

## 安装

从 GitHub 直接装：

```
plugin_manager install_bundle  →  在插件页「添加插件」里填 github:<你的用户名>/dsh-refusal-guard
```

本地开发也可以 `link:` 挂进 `profiles/desktop`，并登记进 `dsh.profile.bundles`：

```
profiles/desktop/package.json
  dependencies:  "dsh-refusal-guard": "link:<本目录绝对路径>"
  dsh.profile.bundles: [ ..., "dsh-refusal-guard" ]
```
